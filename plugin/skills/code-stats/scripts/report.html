How files are classified

Every git-tracked file gets exactly one area (the first matching rule of code_stats.areas, or of the default areas), one kind, a language (from the extension, a shebang line or the linguist-language attribute) and a module. LOC (lines of code) = non-blank, non-comment lines; Lines = all lines. Binary and media files are asset: sized, never line-counted. A file is unclassified when its kind is other or no area rule matched it, so it fell to the default area. --explain <path> prints the rule behind each value of one file.

code
Hand-written source in a programming, markup or style language
test
Code a test convention below matches; a file in a test folder that is not code is a fixture (or docs)
docs
Markdown, MDX, reStructuredText, AsciiDoc, text; files with the linguist-documentation attribute
config
JSON, YAML, TOML, XML, dotfiles and build files, outside areas marked content: true
data
CSV, NDJSON, RDF; and structured files inside areas marked content: true
generated
Lockfiles, generated folders and names, protobuf output, files with the linguist-generated attribute, files headed by a “@generated” or “DO NOT EDIT” banner
fixture
Fixture, snapshot and mock folders, Go’s testdata/, and files in test folders that are not code
vendored
vendor/, third_party/, node_modules/, submodules and files with the linguist-vendored attribute; left out of the totals unless the report was made with --include-vendored
asset / other
Binary and media files; symbolic links and anything no rule matched (charted together as “other”)
