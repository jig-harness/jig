## Executive summary

execa is a mature, well-tested library with almost no written delivery
process, and this run finds one fact the hand-run audit could not: its CI is
not a merge gate. `main` is unprotected, so the nine-leg test matrix, the
linter and the link checker report on every pull request but cannot stop a
merge. Everything else matches the earlier picture: no agent instruction file,
no hooks, no written contribution or release process, excellent product
documentation, and no generated files to keep fresh. The highest-leverage
moves are to make the existing CI required (a settings change plus moving
lint and the link check out of a single matrix leg), to write one short
instruction or contributing file naming `npm test` as the gate set and the
release steps, and to pin the workflow's actions with an updater. Deploy,
feature-pipeline and parallel-agent practices do not apply to a library of
this shape.

## Gap analysis (ranked: leverage × effort)

### P1-1 Make the existing CI a merge gate

- **Finding**: `main` is unprotected; `.github/workflows/main.yml` runs lint and
  the link check only when `matrix.os == 'ubuntu' && matrix.node-version == 26`.
- **Recommendation**: move lint and lychee into their own always-run job, then
  require that job and the test matrix on `main` with a ruleset.
- **Module / maturity target**: M1 Lite; **Ref**: `M1/ci-runs-gates-on-pr`

### P1-2 Write down the gate set and the release steps

- **Finding**: `npm test` is the gate set but no document says so; releases
  are visible only as version commits and tags.
- **Recommendation**: a short `.github/contributing.md` (or `AGENTS.md`)
  naming `npm test`, the regression-test habit, and the release steps.
- **Module / maturity target**: M0 Lite, M10 Lite, M7 Lite; **Ref**:
  `M0/universal-instruction-file`

### P1-3 Pin the workflow's actions and keep them updated

- **Finding**: every `uses:` is a mutable major tag; no Dependabot or Renovate
  configuration.
- **Recommendation**: pin to commit SHAs and add `.github/dependabot.yml` for
  `github-actions`.
- **Module / maturity target**: M1 Standard; **Ref**:
  `M1/third-party-automation-pinned-and-updated`

## Drift findings

- The test runner is `node --test` under c8 (`package.json:21`), not ava as the
  2026-07-19 report says; the switch happened in a commit titled "Tweaks"
  with no rationale.
- `.github/codecov.yml` waits for 6 uploads while the matrix now uploads 9.
- `npm test` and CI run different sets: CI adds the link check, locally lint
  runs everywhere, in CI on one leg.
