# Greenfield adoption

Starting a new project with groundwork from day one.

## The shape

1. **Kickoff methodology** — run the structured bootstrap in
   [seeds/project-kickoff/](../seeds/project-kickoff/) (11 phases:
   requirements discovery → architecture → red-team critique in a **fresh
   session** → synthesis → repo bootstrap → plan review → scaffolding → agent
   hierarchy → implementation planning → tracker population). Its
   Lite/Standard/Enterprise tiers map directly onto groundwork's
   [profiles](../profiles/).
2. **Pick a profile** — during the repo-bootstrap phase, adopt the profile's
   modules at their target maturity from the start: instruction file +
   glossary (M0), gate set + CI (M1), derived-file inventory (M2), and — for
   Team/Standard up — docs governance (M4), ADRs (M5), and the delivery
   pipeline templates (M6).
3. **Wire the learning loop early** (even Lite): a place to file misses and a
   habit of turning them into checks costs almost nothing at day one and
   compounds forever.

## Why kickoff + modules, not just kickoff

The kickoff methodology ends where a project *starts* (tracker populated,
plans reviewed). The modules are the operating system for everything after:
keeping instructions fresh, gates honest, docs governed, reviews layered, and
the process learning. Greenfield projects get both for the price of following
the kickoff's bootstrap phase with groundwork templates at hand.

**Kernel status**: this path deepens in Phase 5, when the kickoff seed is
folded in properly (its templates merged with M6's, its phase docs updated to
reference modules). Until then: use the seed as-is; where the seed and a
module README disagree, the module README wins.
