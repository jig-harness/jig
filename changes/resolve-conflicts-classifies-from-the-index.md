### Changed

- **Breaking:** `resolve-conflicts` requires Git 2.41 or newer, up from 2.40: it reads attributes with `git --attr-source`. Upgrade Git before updating the plugin; with an older Git, `conflict-map.ts` and `check-resolution.ts` stop with an error naming the version.

### Fixed

- `resolve-conflicts` classifies the conflicted paths from what the commit will carry, not from the working tree: `conflict-map.ts` and `check-resolution.ts` read `.config/jig.yaml` (or the file `JIG_OVERLAY` names inside the repository) and the change-area catalog from the git index (following the symbolic links the index holds, with `/` the only path separator; a link whose target leaves the repository is refused, never read from disk) and every attribute (classification and the reconstruction of git's automatic merge) from the index's regular `.gitattributes` files alone (`git --attr-source`): `$GIT_DIR/info/attributes`, the file `core.attributesFile` names and the system's attributes file decide nothing either, and the automatic merge is reconstructed under no configuration but the repository's rename-detection settings and `core.useReplaceRefs`, so a merge driver configured for the repository, the user, the system or the environment does not run, while the repository's replace refs and its submodules' repositories are still read, so a submodule git fast-forwarded is not reported as a conflict. The conflict-marker scan of staged changes reads every added line whatever an attribute says the file is, skipping only content git would call binary (a zero byte in its first 8000 bytes, counted as bytes). A path's marker size is taken from the markers git wrote into it when it is first mapped, so it holds after the attribute that set it is gone, and markers are also looked for at the size the index declares. An index link with an empty target cannot be read through. A filename that holds a literal backslash, a link retargeted only on disk, an untracked or ignored `.gitattributes` file, and a staged link named `.gitattributes` no longer let a resolution pass that the committed catalog or attributes would reject. A change to the configuration or the catalog takes effect once it is staged. `check-resolution.ts` no longer reports a declaration whose working tree differs from the index, since the working tree decides nothing. A relative `JIG_OVERLAY` is taken from the working directory, as every other configuration reader takes it, and a configured path that names a directory, or ends in `/` after a file, cannot be read. While `.config/jig.yaml` itself is unmerged, `conflict-map.ts` still records the conflicts and marks the map incomplete, so `check-resolution.ts` refuses until the file is staged and the conflicts are mapped again.
