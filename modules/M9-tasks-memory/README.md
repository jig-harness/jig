# M9 — Tasks & memory (stub)

**What problem this solves.** Work tracking that's just a list doesn't drive
process (labels are folksonomy, not triggers), and agent knowledge evaporates
between sessions. This module covers tracker discipline where labels *fire
gates*, plus persistent agent memory tiers.

**Invariant.** Issues carry a mandatory label taxonomy in which flag labels
are process triggers (migration → migration review gate; API change → contract
gates; HITL → autonomy revoked); work is tiered *what* (tracker) / *how*
(persistent multi-session memory) / *in-session* (task lists); recurring
multi-phase work uses formulas with REQUIRED phases (e.g., staging
verification before production).

**Port sources**: docomply Linear taxonomy + planning templates (tracker-
agnosticized), beads formulas concept, memory-promotion flow (with M8).
Ports in Phase 5.
