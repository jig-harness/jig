# Product requirements: Saved views

## Problem statement

People re-apply the same filters every visit; there is no way to keep one.

## Users and personas

Primary: the returning analyst who lives in one filtered slice of the data.

## Requirements

- FR-1: a user can save the current filter set under a name.
- FR-2: a user can re-open a saved view in one action.

### Non-functional requirements

- Opening a saved view feels instant on a normal connection.

## Success metrics

- Half of weekly-active users create at least one saved view in month one.
- Median filters-per-session drops once saved views exist.

## Scope

In: create, open, rename, delete a saved view.
Out: sharing a view with another user (a later phase).
