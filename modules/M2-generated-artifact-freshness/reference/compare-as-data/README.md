# Compare as data: one-way derivation for structured artifacts

Part of [M2 Generated-artifact freshness](../../README.md).

A contract artifact (an API description, a schema, the JSON form of
generated types) is written by a generator and then touched by a formatter,
a key sort or a line-ending rule. Its bytes differ from the generator's
fresh output while its content does not. A byte comparison then reports
drift on every run, every finding converges on "regenerate" as the fix, and
real drift hides among the false ones; the team learns to re-run the
generator without reading the diff.

`compare-as-data.ts` parses both copies and compares the data they encode.
Key order and formatting fall away, and each difference is named by its path
in the data. For every one the remedy is the same: regenerate from the
source. Derivation runs one way; an artifact is never edited to match its
source, and a constraint the artifact needs that the source cannot express
is added to the source layer, which must be able to emit everything the
artifact carries.

## Usage

```bash
bun compare-as-data.ts [--command <regenerate command>] <committed> <fresh>
```

- `<committed>`, `<fresh>`: the artifact in the repository and the
  generator's fresh output, each JSON or YAML by its extension (`.json`,
  `.yaml`, `.yml`). Either may be in either syntax, so a YAML artifact can
  be compared with a JSON dump.
- `--command`: the regenerate command, named in every finding as the fix.

Both sides pass through the same parse. Whatever further normalization a
comparison needs (dropping a timestamp field, sorting a list whose order
the generator does not fix), apply it to both sides, in one function: a
normalization applied to one side only makes every later fix to it look
like drift of every committed artifact, until each is regenerated by hand.

The script imports helpers from the Jig repository's `lib/` (`cli.ts`,
`files.ts`, `findings.ts`, `record.ts` and the vendored YAML parser) by
their path from the repository root (`../../../../lib/`), so run it from a
pinned Jig checkout, or vendor it with `lib/` keeping that relative layout
(or rewrite the imports), as the toolchain note in
[M1's mappings](../../../M1-gates-enforcement-ladder/mappings.md) describes.

## Findings

Every difference is reported, not only the first: a changed value
(`$.info.version: "1.0.0" committed, "1.1.0" fresh`), a key one side lacks
(`$.paths./reports: fresh has it, committed does not`), a list of another
length (and every changed element at the indexes both lists have), a value
of another kind. Findings print as
`<committed>: [compare-as-data] problem` and `fix: remedy` lines, and under
GitHub Actions also as annotations
([`lib/findings.ts`](../../../../lib/findings.ts)).

## Exit codes

| Exit | Meaning |
| --- | --- |
| 0 | the two parse to the same data: `compare-as-data: OK — <committed> and <fresh> encode the same data` |
| 1 | they differ |
| 2 | a file cannot be read or parsed, is empty or holds no document (only comments, markers or a byte-order mark; an explicit `null` is a document), has an extension the script does not read, uses a list or a mapping as a mapping key, which parsing turns into a string (a scalar key is compared as its string, as JSON holds it), holds an integer past 2^53 as a value or a mapping key, which parsing may round onto its neighbour, or holds a number past the range of a double, which parses to infinity (YAML's own `.inf` is a value, not an overflow; a decimal with more significant digits than a double holds is rounded the same way and is not detected) |

## In a chain of derived files

Where one artifact derives from another (migrations, then a schema dump,
then the types a build reads, then a client), each link has its own check,
with its own fresh output on the right-hand side: a check that compares only
the ends of the chain cannot say which link went stale, and a link checked
by nobody is where a hand edit lives longest. All derived schemas come from
the one source at the head of the chain; a second generator from the same
source is fine, a second artifact maintained by hand beside the generated
one is not.

## Wiring it into CI

As the `check` of the artifact's entry in the
[generated-file inventory](../inventory/): generate to a temporary path,
compare, and let the entry's `command` be the fix the finding names:

```yaml
- outputs: ["api/openapi.json"]
  source: ["src/routes/**/*.ts"]
  command: "bun tools/generate-spec.ts api/openapi.json"
  check: >-
    bun tools/generate-spec.ts /tmp/openapi.json &&
    bun reference/compare-as-data/compare-as-data.ts --command "bun tools/generate-spec.ts api/openapi.json" api/openapi.json /tmp/openapi.json
```

## Try it

```sh
cd fixtures
bun ../compare-as-data.ts committed.json fresh-reformatted.json  # exit 0: other key order and whitespace
bun ../compare-as-data.ts committed.json fresh-same.yaml         # exit 0: the same data in YAML
bun ../compare-as-data.ts committed.json fresh-differs.json      # exit 1: three differences, each by path
bun ../compare-as-data.ts committed.json not-json.json           # exit 2: could not check
```

The self-test beside the script, `compare-as-data.test.ts`, runs every
fixture pair, the usage errors and the comparison's cases.
